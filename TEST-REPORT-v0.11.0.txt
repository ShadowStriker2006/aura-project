IMPLEMENTED CORRECTIONS
-----------------------

1. Replay/control gating
   Previous behavior:
     availability.control_estimate=false replaced the entire replay with an
     unavailable message even though Rust had returned frames and events.

   Corrected behavior:
     - positions=false/no usable coordinates -> movement unavailable;
     - positions=true/control=false -> movement, stats, events, seeking, and
       playback remain available with an explicit control reason;
     - positions=true/control=true -> map-specific estimate and graph enabled.

2. Schema version 2
   Added:
     - game_version;
     - coordinate model ID, provenance, and canvas transforms;
     - control_model ID, topology, anchors, and anchor provenance;
     - separate positions_reason and control_reason.

   The frontend still accepts the schema-1 reason field as a fallback.

3. Map-specific coordinates
   Summoner's Rift:
     model: summoners_rift_rect_v1
     projection: 0..15000

   Howling Abyss:
     model: howling_abyss_rect_v1
     projection: 0..12800
     provenance: aura_match_v5_calibration_16_15_v1

   Unknown maps:
     model: observed_extent_v1
     movement-only padded observed extent

   Safe raw coordinate limits remain broader than either display projection.
   Small edge samples are clamped instead of discarded. A substantial
   calibrated-map mismatch fails control closed and preserves movement using
   observed extents.

4. Howling Abyss control model
   Backend guards require an early frame at <=30 seconds, at least three valid
   positions for each team, compact same-team spawn clusters, expected opposite
   base zones, and sufficient separation.

   The frontend projects champions onto the per-match blue-to-red bridge axis,
   evaluates bounded level/gold-weighted one-dimensional pressure, and renders
   a straight perpendicular frontier. A single crossing produces lane-territory
   percentages. Multiple crossings display Split pressure, suppress the false
   single frontier, and retain an integrated pressure percentage.

5. Actual terrain

       SHA-256: 829b0d75dd765cfed406b5c591b546436f32e95c4445e3f378e89a235f6782fc

KNOWN BOUNDARIES
----------------

1. Local artifacts are NOT Authenticode-signed. Public distribution must use
   the configured GitHub release workflow with a trusted certificate and
   timestamp. The workflow refuses a public release when signing is absent.

2. The NSIS installer was built and structurally verified but was not installed
   over the user's existing Aura installation. A clean-install/upgrade/uninstall
   matrix remains a release-candidate task because it intentionally changes the
   user's installed application state.

3. Riot formally documents Timeline x/y as integers but does not guarantee map
   bounds, origin, base coordinates, brush polygons, or recall state. The ARAM
   projection is explicitly Aura's empirical v1 calibration and fails closed.

4. Data Dragon terrain is not a brush or walkability mask. Aura cannot truthfully
   prove that a sampled champion is inside a bush.

5. Timeline positions are coarse snapshots. Interpolation is visual only. A
   large base transition can be transport, death/respawn, normal movement, or
   another return; Aura does not label it as an exact observed recall cast.

6. The process working-set sample covers only the isolated parent executable at
   startup, not the complete WebView2 process tree and not an in-match workload.
   It must not be presented as proof of the original <30 MiB whole-app target.
