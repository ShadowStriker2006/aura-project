OFFICIAL RANK AND CHAMPION MASTERY
---------------------------------

Implemented:

- Typed Champion-Mastery-V4 platform-route request using encrypted PUUID.
- Rust-only X-Riot-Token handling with no API key in frontend code or logs.
- Streaming 16 MiB response limit and bounded network timeout.
- Two-minute, per-PUUID, volatile RAM cache cleared on identity/key changes.
- ID filtering, points-descending/ID-ascending sorting, reliable HashSet
  deduplication, and a 200-entry backend cap.
- Independent mastery request lifecycle: mastery failure does not fail rank or
  match history.
- Generation and selected-profile guards against late old-player responses.
- Top-five Profile mastery cards linked to champion details.
- Champion detail mastery level, points, progression, and last-played display.
- Home hero summary for official Solo/Duo rank, top mastery, and account level.
- Official LP, wins, losses, win rate, mini-series, hot-streak, veteran, and
  new-ranked-entrant status display for Solo/Duo and Flex.
- Explicit loading, empty, unavailable, missing-key, and bad-identity states.
- Data Dragon readiness gating and rerendering for mastery portraits/actions.
- Accessible rank groups, mastery live status, and non-star-only mastery text.

LIVE-DATA / PUBLICATION / PERFORMANCE LIMITS
--------------------------------------------

1. A real mastery/rank acceptance test still requires a valid, non-expired Riot
   API key and a reachable account. Fixtures and DTO tests do not substitute
   for production-key acceptance.
2. Riot development keys expire and must not be embedded in a binary. The user
   must replace an expired key through Settings/Windows Credential Manager.
3. These local artifacts are not Authenticode-signed. Public installers must be
   built, signed, and timestamped by the protected release workflow.
4. Clean install, upgrade-over-an-existing-Aura-install, and uninstall were not
   executed because that would overwrite the user's current installed copy.
5. The root Rust/Tauri process is small, but the complete WebView2 process tree
   is not under 30 MiB. One 15-second observation measured 7 processes at
   171.54 MiB private bytes / 372.00 MiB summed working set. Shared/GPU page
   accounting and Windows residency vary, but the original strict total-RAM
   target is not met by the Tauri/WebView2 architecture. Meeting a true total
   <30 MiB ceiling would require a native non-WebView UI or a headless mode.
6. Existing Spotify OAuth/Connect and live LCU behavior were not reauthorized
   against real accounts in this mastery-focused release.
